# Context、人格与工具如何分层

> **第二部 · Agent 系统与平台 · 第5章**
>
> 撰写日期：2026-08-31（整理自 2026-07-04 的团队 Bot 实践）

## 结论

通用模型进入真实协作后，体验差异主要来自模型之外：它以什么身份出现、每轮获得什么 Context、能够调用什么工具、权限由谁裁决。

## 1. 人格是行为契约

有效的人格不是形容词清单，而是会改变具体回复的规则：

- 正事先给结论，闲聊才允许发挥风格；
- 不确定的事实先查证，查不到就明确说不知道；
- 不伪装成看见了未获得的消息；
- 不输出凭证和私人数据；
- 涉及方向与责任的问题，知道什么时候交还给人。

检验标准很简单：删除一条人格规则后，如果没有任何真实回复会改变，这条规则只是营销文案。

## 2. Context 分四层

| 层 | 内容 | 机制 |
| --- | --- | --- |
| 身份层 | 人格、边界、长期规则 | 少量常驻 |
| 会话层 | 当前对话与任务状态 | 随会话维护 |
| 现场层 | 时间、发送者、回复链、当前页面 | 每轮自动注入 |
| 检索层 | 知识库、团队记忆、实时数据 | 按需获取 |

回复链是团队聊天中经常被忽略的现场信息。短句、玩笑和指代离开父消息后往往无法正确理解；这类错误不该靠换更强模型解决，而应补足现场。

## 3. 模型理解，工具执行

带副作用的能力采用统一模式：

```text
自然语言请求
→ 模型识别意图并生成参数
→ 代码验证身份、权限和参数
→ 确定性工具执行
→ 返回可核查结果
```

模型不直接决定谁能写文件、读取日历或发布消息。权限拒绝也要返回明确原因和允许的下一步，避免模型盲目重试变体。

## 4. 主动性需要预算

允许 Agent 不被点名也发言，意味着它开始消耗公共注意力。默认应保持沉默，只在少数高价值条件下介入，并使用硬配额或随群活跃度变化的比例限制。

主动性不是“更像人”就越好，而是每次打扰是否值得。

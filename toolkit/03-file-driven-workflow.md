# 文件驱动的复杂任务工作流

> **工具箱 · AI 协作**
>
> 撰写日期：2026-08-31（合并结构化编码与长文协作实践）

## 适用场景

需要跨多个步骤产出代码、报告、方案或设计，并且任务可能跨会话、由多人或多个 Agent 接力完成。

核心原则是：**讨论可以发生在对话里，状态和决策必须落到文件里。**

## 四段式任务定义

```text
目标：最终要达到什么状态。
输入：已有文件、素材、限制和事实源在哪里。
输出：产物的路径、格式和验收方式。
步骤：先做什么、哪里必须提问、如何验证、失败后怎样恢复。
```

## 推荐流程

```text
现场考古
→ 对齐目标、读者、范围、落点与新旧关系
→ proposal.md：需求和不做什么
→ design.md：模块、数据和边界
→ tasks.md：可独立验证的任务
→ progress.md：当前状态、阻塞和下一步
→ 分步实现与验证
```

上一步已经沉淀到文件后，下一步可以使用干净会话继续，不依赖越来越长的聊天历史。

## 对齐清单

开始长文或复杂产品前，至少确认：

1. 写给谁、解决什么问题；
2. 哪条主线最重要；
3. 哪些素材深读，哪些明确不纳入；
4. 产物放在哪里，谁拥有它；
5. 已有内容是保留、重写还是并存；
6. 本轮交付完整成品还是可评审骨架。

## 多 Agent 的使用条件

只有当任务能按文件或模块划分、子任务之间依赖较少、结果可以独立验证时，才适合并行。监工只维护整体目标和 `progress.md`，子 Agent 只读取完成自己任务所需的材料。

不要要求“每一行代码都有对应单测”。更可靠的验收方式是：关键行为、边界条件和历史缺陷有回归测试，并通过项目已有的类型检查、静态检查和构建。

## 完成标准

- 产物路径明确且可打开；
- 验收命令已经运行；
- 未解决问题写入 `progress.md`，不藏在聊天里；
- 外部发布、覆盖或删除仍遵守权限和人机交接点。

# 团队 AI：从 Bot 到团队成员

> **第三部 · 产品与应用 · 第10章**
>
> 撰写日期：2026-08-31（合并团队 Bot 与注意力路由实践）

## 结论

团队 AI 的价值不在于群里多了一个聊天入口，而在于它能否在正确的上下文中承担稳定职责，同时不过度占用公共注意力。

## 1. 成员感来自角色与责任

名字、头像和语气可以降低沟通距离，但成员感最终来自三个可验证的预期：

- 它知道自己负责什么；
- 正事上可靠，查不到就不编；
- 知道什么时候沉默、什么时候交还给人。

出场演示应该使用真实能力和真实数据，不预埋第二天无法复现的台词。

## 2. Context 决定它是否真的懂团队

团队 Bot 需要身份、会话、现场和检索四层 Context。成员画像和知识库不是越多越好；只有与当前问题有关、且请求者有权访问的信息才能进入当前轮次。

回复链、发送者身份和当前群聊是廉价但高价值的现场信息，应该由系统自动提供。

## 3. 推送不是摘要，而是注意力路由

团队知识上新时，卡片不应复述全文，而应让成员快速决定：谁需要读、为什么、重点在哪里。

一个足够小的结构是：

| 行 | 回答的问题 |
| --- | --- |
| 一句话 | 这是什么 |
| 建议谁看 | 和谁的任务有关，为什么 |
| 重点看 | 最值得进入原文的位置 |
| 作者与链接 | 从谁来，去哪里核查 |

作者不能被点名给自己；点名、格式和权限等硬约束由代码验证。没有相关读者时可以不推送。

## 4. 主动发言要有硬预算

主动插话只适用于少数情况：长时间无人回应且能查证的问题、重要事实纠正、与团队文化高度匹配的轻量互动。配额应随群活跃度变化，冷群接近沉默，不能用固定频率刷存在感。

## 5. 衡量团队价值

早期先看目标成员中谁真正使用过，再看频次和留存；同时观察 Bot 是否减少了找资料、重复解释和人工路由的时间。总消息数和 token 消耗不是产品价值。

# 内容产品的编辑抽象：给用户语义模型，而不是代码

> **第三部 · 产品与应用 · 第12章**
>
> 撰写日期：2026-08-31（整理自 2026-07-13 的实践）

## 结论

给非技术用户维护内容站时，网页里的代码编辑器仍然是代码工具。真正的零代码编辑，需要在源文件和用户之间建立一层语义模型：用户操作标题、正文、卡片、图片和链接，而不是文件、标签和语法。

## 1. 为什么源码套壳仍然难用

| | 源码编辑器 | 语义编辑器 |
| --- | --- | --- |
| 用户看到 | 文件、标签、语法 | 页面中的业务对象 |
| 需要理解 | 工程结构 | 内容含义 |
| 出错方式 | 破坏语法和页面结构 | 只修改允许的属性 |
| 框架变化 | 用户需要重新学习 | 由适配层吸收 |

## 2. 三层结构

```text
用户编辑标题 / 卡片 / 图片
→ 语义模型校验对象和属性
→ 适配层写回真实数据或源文件
```

交互自然会变成所见即所得画布和对象属性面板。用户的动作是“选中这张卡、换图片”，而不是“打开哪个文件、改第几行”。

## 3. 抽象层取决于用户能力

| 用户 | 合适的编辑抽象 |
| --- | --- |
| 工程师 | 规格、结构化指令、代码 diff |
| 熟悉后台的运营 | 内容模型、表单和预览 |
| 非技术业主 | 业务对象、画布和安全默认值 |

零代码不是把技术界面藏起来，而是重新定义用户真正需要操作的对象。

## 4. AI 应生成候选，不应绕过模型

AI 可以帮用户改写文本、生成卡片或建议图片，但结果仍要落到同一语义模型中，经过字段、权限和预览校验。否则 AI 会重新把不可控的源码修改带回产品。
